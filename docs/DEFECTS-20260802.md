## 缺陷 A：能播但出不了声 —— url-smart 返回了垃圾「URL」

### 现象
- 前端点播放，`<audio>` 在播但无声
- 实测：`/api/music/url-smart?id=7a66af...&sources=netease,kugou,kuwo&q=Die For You`
  返回：`{"url":"{\"msg\":\"参数错误\",\"code\":400}{\"msg\":\"参数错误\",\"code\":400}"}`
- 前端把这段**错误 JSON 字符串**当流地址塞给 audio → 播放器拿不到真实音频 → 无声

### 根因
`ai-radio/server/ncm.mjs` `getUrlSmart()` 里：
- `sources` 含 `kuwo` 时，Meting 对 kuwo 返回的是**错误 JSON 字符串**（`{"msg":"参数错误","code":400}`）
- `extractUrlFromRaw()` 没校验「返回的是不是合法 http(s) URL」，把错误串当 URL 返回了
- `getUrlSmart` 成功分支 `if (!url) continue` 判断不了「字符串非空但是垃圾」

### 修复要求（Cursor）
1. `getUrlSmart` / `extractUrlFromRaw`：**任何不以 `http(s)://` 开头的返回值一律视为失败**，继续尝试下一个源
2. `kuwo` 源要么修好、要么从 `sources` 默认列表里拿掉（前端 `api.ts` 现在传 `netease,kugou,kuwo`）
3. `url-smart` 路由：最终 url 也要校验合法性；不合法就 `404 no url found`，不要 `200 + 垃圾串`
4. 验证：`curl "/api/music/url-smart?id=7a66af1c054857487735347aec053546&sources=netease,kugou&q=Die For You"` 必须返回**真实 mp3 地址**（`http...mp3`），不能再是错误串

## 缺陷 B：网易云扫码没反应

### 现象
- 前端「扫码登录网易云」出码后，扫了没反应，一直停在「请扫码」

### 排查结论（已排除）
- 后端链路**本身是通的**：`login_qr_key` → `login_qr_create` → `login_qr_check` 实测正常（返回 801 等待扫码）
- 不是库版本问题（4.36.1）

### 疑点（Cursor 排查）
1. **`LoginPanel.tsx` 轮询**：`startQr` 只在点「扫码登录」按钮时调用，轮询 `setInterval 2000ms` 调 `qr-check`。检查：
   - 扫完码后 `check.code` 是否变化？前端只处理 `200`，但网易云中途会先返回 **802（已扫码，待确认）**——前端 `setQrCode(check.code)` 有显示分支（802='已扫码确认登录'），**但轮询是否在 802 时继续**？
   - `check.code === 200 && check.key` 才切歌单；若 check 返回结构里 `key` 字段名不对（后端返回的是 `{code:200, key:sessionKey}`），确认字段一致
2. **后端 `qr-check` 返回结构**：`qrCheckForPlatform` 成功返回 `{code:200, key, platform, user}`；确认前端读 `check.key` 对得上
3. **二维码生成用的 key 与轮询的 key 一致**：`LoginPanel` 里 `setQrKey(keyJson.key)` 但轮询闭包用的是 `keyJson.key`，应一致；确认没被 `qr-key` 的 5 秒冷却（`QR_KEY_COOLDOWN_MS=5000`）坑到（连续点击会抛「请求过于频繁」被 catch 吞掉 → 界面无反应）

### 修复要求（Cursor）
1. 前端扫码后状态机完整处理：801→802→200（含确认步骤），802 时继续轮询而不是停
2. `startQr` 的 catch 不能静默吞错——至少 console.error + 界面提示
3. 验证：手机网易云 App 扫码 → 界面 802「已扫码，确认登录」→ 点确认 → 200 → 歌单列表出来
